## 二、编译命令

### 2.1 标准编译（Debug/x64）

```cmd
cd /d "D:\Program Files\VisualStudio\MSBuild\Current\Bin" && MSBuild.exe "D:\source\repos\xxx\xxxCore\xxxCore.vcxproj" /p:Configuration=Debug /p:Platform=x64 /verbosity:minimal
```

> **为什么要 `cd /d` 进 MSBuild 目录？** 因为 cmd.exe 的 `/s /c` 引号剥离机制会将带引号的 MSBuild 路径错误展开。先进目录再执行 MSBuild 可绕开此问题。

### 2.2 Release 编译

```cmd
cd /d "D:\Program Files\VisualStudio\MSBuild\Current\Bin" && MSBuild.exe "D:\source\repos\xxx\xxxCore\xxxCore.vcxproj" /p:Configuration=Release /p:Platform=x64 /verbosity:minimal
```

### 2.3 32 位 Win32 编译

```cmd
cd /d "D:\Program Files\VisualStudio\MSBuild\Current\Bin" && MSBuild.exe "D:\source\repos\xxx\xxxCore\xxxCore.vcxproj" /p:Configuration=Debug /p:Platform=Win32 /verbosity:minimal
```

```cmd
cd /d "D:\Program Files\VisualStudio\MSBuild\Current\Bin" && MSBuild.exe "D:\source\repos\xxx\xxxCore\xxxCore.vcxproj" /p:Configuration=Debug /p:Platform=x64 /p:PreferredToolArchitecture=x64 /verbosity:minimal
```

## 五、常见编译错误及解决方案

### 5.1 C4819：中文注释编码警告

**症状：**

```
warning C4819: The file contains a character that cannot be represented in the current code page (936). Save the file in Unicode format to prevent data loss.
```

**根因：** MSVC 在简体中文 Windows 下默认代码页为 GBK（936），源代码中的 UTF-8 中文字符无法被 GBK 代码页正确解析。

**解决方案：**

1. **推荐**：在 vcxproj 的每个配置的 `<ClCompile>` 中添加：

   ```xml
   <AdditionalOptions>/utf-8 %(AdditionalOptions)</AdditionalOptions>
   ```

   这等效于同时指定 `/source-charset:utf-8 /execution-charset:utf-8`，告知编译器源文件和执行字符集均为 UTF-8。

   > 本项目已在所有四个配置（Debug/Release × x64/Win32）中添加此选项。

2. **备选**：在文件头部添加 `#pragma execution_character_set("utf-8")`（仅限 MSVC，且不如 `/utf-8` 可靠）。

3. **防止文件编码问题**：所有 `.cpp` / `.h` 文件应保存为 **UTF-8 无 BOM** 格式。UTF-8 with BOM 在某些 MSVC 版本中可被识别，但在 Git 差异对比和跨平台工具中可能引发问题。
   - 方法：VS 中「文件 → 高级保存选项 → Unicode (UTF-8 无签名)」
   - 或使用 VS Code：「文件 → 以编码保存 → UTF-8」

### 5.2 C4244：窄化转换警告（`uint64_t` → `uint32_t`）

**症状：**

```
warning C4244: 'argument': conversion from 'uint64_t' to 'NodeId', possible loss of data
```

**根因：** 旧版 `Node::store_offset` 定义为 `uint64_t`，但 `ReadStore` / `SetStoreOffset` / `AllocateStore` 等接口都使用 `NodeId`（`uint32_t`），20+ 处调用产生窄化转换。

**解决方案：** 将 `store_offset` 从 `uint64_t` 改为 `NodeId`（`uint32_t`）。`Node` 结构体从 16B 缩小至 12B，同时消除全部 C4244 警告。

**参考提交：** `64e00b7`

### 5.3 C4099：前向声明 class/struct 不匹配

**症状：**

```
warning C4099: 'QuantifiedEqSubst': type name first seen using 'class' but now seen using 'struct'
```

**根因：** 头文件中前向声明为 `struct`，实际实现为 `class`，或反之。

**解决方案：** 统一前向声明与实际定义的关键字。

### 5.4 LNK 链接器 OOM（内存耗尽）

**症状：**

```
LINK : fatal error LNK1257: code generation failed
```

或 MSBuild 进程无响应/崩溃，伴随高内存占用。

**根因：** 32 位 MSBuild 链接器在处理大型编译产物（特别是包含大量模板展开的 C++ 代码）时，地址空间限制（2GB）不足。

**解决方案：** 编译时指定使用 64 位工具链：

```cmd
/p:PreferredToolArchitecture=x64
```

## 六、中文编码问题汇总

### 6.1 问题分类

| 问题 | 场景 | 表现 |
|------|------|------|
| **源码编码** | .cpp/.h 文件含中文注释或字符串 | C4819 编译警告 |
| **控制台输出** | `std::cout` 输出中文字符串 | 乱码/问号 |
| **文件读写** | 读写含中文的输入/输出文件 | 乱码 |
| **Git 差异** | UTF-8 BOM 文件在 Git diff 中 | 文件头部显示为特殊字符 |

### 6.2 源码编码问题

**解决方案（已配置）：**

在 vcxproj 的每个 `<ClCompile>` 节中添加：

```xml
<AdditionalOptions>/utf-8 %(AdditionalOptions)</AdditionalOptions>
```

这同时设置：
- `/source-charset:utf-8` — 源文件以 UTF-8 解释
- `/execution-charset:utf-8` — 执行字符集为 UTF-8

**注意事项：**
- `/utf-8` 会覆盖 `/validate-charset` 的有效性检查。如果 MSVC 版本较旧不支持，可用独立的 `/source-charset:utf-8 /execution-charset:utf-8` 替代。
- 确保所有 `.cpp` / `.h` 文件保存为 **UTF-8 无 BOM** 格式。

### 6.3 控制台输出编码

在 `main()` 入口设置：

```cpp
SetConsoleOutputCP(CP_UTF8);
```

**注意：** 这仅在 Windows 10 版本 1903+ 上可靠工作。旧版本 Windows 可能需要同时设置：

```cpp
SetConsoleCP(CP_UTF8);        // 输入编码
SetConsoleOutputCP(CP_UTF8);  // 输出编码
```

**备用方案（旧 Windows）：**

```cpp
// 需要 <io.h> 和 <fcntl.h>
_setmode(_fileno(stdout), _O_U16TEXT);
// 但 _O_U16TEXT 会使 cout 与 printf 混用出问题，不推荐与 std::cout 共用
```

### 6.4 文件编码检查方法

**方法一：VS Code / Notepad++**
- 右下角状态栏显示文件编码
- 通过「以编码保存」选择 UTF-8

**方法二：PowerShell**

```powershell
# 检查文件编码
[System.Text.Encoding]::Default.GetString([System.IO.File]::ReadAllBytes("file.cpp")) -match "[^\x00-\x7F]"
```

**方法三：Git Bash**

```bash
# 检查文件是否有 BOM
head -c 3 file.cpp | xxd
# 如果开头是 EF BB BF，则有 BOM
```

### 6.5 中文编码检查清单

遇到中文相关问题时依次排查：

- [ ] vcxproj 是否配置了 `/utf-8`？
- [ ] 源码文件编码是否为 **UTF-8 无 BOM**？
- [ ] 控制台输出是否调用了 `SetConsoleOutputCP(CP_UTF8)`？
- [ ] 文件读写是否使用 UTF-8 编码打开流？（`std::ifstream` 默认使用系统 locale，需显式设置）
