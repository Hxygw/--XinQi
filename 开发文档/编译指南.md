## 二、编译命令

> **注意：MSBuild 不在 PATH 中**，需要使用完整路径或先 `cd` 进 MSBuild 目录。推荐在脚本中直接引用完整路径。

### 2.1 一键构建（推荐）

项目根目录下提供了构建脚本：

```cmd
build_roomserver.bat
```

该脚本会自动完成：构建 XinQiCore → 构建 RoomServer → 构建前端 → 打包 zip。

### 2.2 分步编译

#### Release/x64

```cmd
"D:\Program Files\VisualStudio\MSBuild\Current\Bin\MSBuild.exe" "D:\source\repos\XinQi\XinQiCore\XinQiCore.vcxproj" /p:Configuration=Release /p:Platform=x64 /verbosity:minimal

"D:\Program Files\VisualStudio\MSBuild\Current\Bin\MSBuild.exe" "D:\source\repos\XinQi\XinQiRoomServer\XinQiRoomServer.vcxproj" /p:Configuration=Release /p:Platform=x64 /verbosity:minimal
```

#### Debug/x64

```cmd
"D:\Program Files\VisualStudio\MSBuild\Current\Bin\MSBuild.exe" "D:\source\repos\XinQi\XinQiCore\XinQiCore.vcxproj" /p:Configuration=Debug /p:Platform=x64 /verbosity:minimal

"D:\Program Files\VisualStudio\MSBuild\Current\Bin\MSBuild.exe" "D:\source\repos\XinQi\XinQiServer\XinQiServer.vcxproj" /p:Configuration=Debug /p:Platform=x64 /verbosity:minimal
```

### 2.3 避免引号路径问题的替代方法

如果 MSBuild 完整路径在引号中导致 cmd.exe 解析异常，可以先进目录再执行：

```cmd
cd /d "D:\Program Files\VisualStudio\MSBuild\Current\Bin" && MSBuild.exe "D:\source\repos\XinQi\XinQiCore\XinQiCore.vcxproj" /p:Configuration=Release /p:Platform=x64 /verbosity:minimal
```

### 2.4 64 位链接器（链接大项目时 OOM 时启用）

```cmd
/p:PreferredToolArchitecture=x64
```

当 RoomServer 链接 `grpc.lib` 等大型库时，32 位链接器可能因内存不足自动重启为 64 位链接器。也可以手动指定：

```cmd
"D:\Program Files\VisualStudio\MSBuild\Current\Bin\MSBuild.exe" "D:\source\repos\XinQi\XinQiRoomServer\XinQiRoomServer.vcxproj" /p:Configuration=Release /p:Platform=x64 /p:PreferredToolArchitecture=x64 /verbosity:minimal
```

## 五、常见编译错误及解决方案

### 5.1 C4819：中文注释编码警告

**症状：**

```
warning C4819: The file contains a character that cannot be represented in the current code page (936). Save the file in Unicode format to prevent data loss.
```

**根因：** MSVC 在简体中文 Windows 下默认代码页为 GBK（936），源代码中的 UTF-8 中文字符无法被 GBK 代码页正确解析。

**解决方案：**

1. **推荐**：在 vcxproj 的每个配置的 `<ClCompile>` 中添加：

   ```xml
   <AdditionalOptions>/utf-8 %(AdditionalOptions)</AdditionalOptions>
   ```

   这等效于同时指定 `/source-charset:utf-8 /execution-charset:utf-8`。

   > 本项目已在所有配置中添加此选项。

2. **备选**：在文件头部添加 `#pragma execution_character_set("utf-8")`。

3. **防止文件编码问题**：所有 `.cpp` / `.h` 文件应保存为 **UTF-8 无 BOM** 格式。

### 5.2 C4244：窄化转换警告（`uint64_t` → `uint32_t`）

**症状：**

```
warning C4244: 'argument': conversion from 'uint64_t' to 'NodeId', possible loss of data
```

**解决方案：** 将 `store_offset` 从 `uint64_t` 改为 `NodeId`（`uint32_t`），同时消除全部 C4244 警告。

### 5.3 LNK 链接器 OOM（内存耗尽）

**症状：** `LINK : fatal error LNK1257: code generation failed` 或 MSBuild 进程无响应/崩溃。

**根因：** 32 位 MSBuild 链接器在处理大型编译产物时，地址空间限制（2GB）不足。

**解决方案：** 使用 64 位工具链（见 2.4 节）。

### 5.4 编译产物大小异常

偶见 Release 编译产物体积远大于预期（如 `main.obj` 达 13MB），这是 `/GL` 全程序优化中间产物，不影响最终 exe 体积。

## 六、中文编码问题汇总

### 6.1 源码编码

已在所有 vcxproj 的 `<ClCompile>` 中配置：

```xml
<AdditionalOptions>/utf-8 %(AdditionalOptions)</AdditionalOptions>
```

同时设置：
- `/source-charset:utf-8` — 源文件以 UTF-8 解释
- `/execution-charset:utf-8` — 执行字符集为 UTF-8

### 6.2 控制台输出编码

在 `main()` 入口设置：

```cpp
SetConsoleOutputCP(CP_UTF8);
```

### 6.3 文件编码检查

使用 VS Code 打开文件查看右下角状态栏，确保为 **UTF-8** 编码。

中文问题排查清单：

- [ ] vcxproj 是否配置了 `/utf-8`？
- [ ] 源码文件编码是否为 **UTF-8 无 BOM**？
- [ ] 控制台输出是否调用了 `SetConsoleOutputCP(CP_UTF8)`？
